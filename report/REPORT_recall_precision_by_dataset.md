# QA / Summarize 分数据集 Recall & Precision 明细报告

**日期**：2025-09-18
**对象**：`src/task_rules.py` 当前方案（`classify_pipeline`，严格两级 user → system）
**配套**：`report/REPORT_task_rules_robustness.md`（总体鲁棒性报告）；本报告把 qa/summarize 两类指标**按数据集拆开**，回答"每个数据集上 recall、precision 各是多少"。
**口径**：

- recall = 判对 / 该类真实总数（已触发；long_text ≤ 2000 字符的样本真实系统不分类，不计入）
- precision = 判对 / 判成该类的总数（分母含误判进来的假阳性）
- 低召回高精度是设计原则：qa/summarize **判了就要对**（precision 优先）；真 QA/Summ 掉到 other 可接受（线上 system 模板兜底）

---

## 一、三句话结论

1. **LongBench（真实流量）**：qa **P 95.1% / R 99.9%**，summarize **P 100% / R 85.2%**——精度几乎无损，唯一精度损失是 qmsum（豁免边界）；唯一召回损失也在 qmsum。
2. **LongBench-v2（官方Multiple Choice选择题模板）**：qa **P 100% / R 0.7%**——MC 选项负规则把非 QA 四域违规清到 0 的同时，把 QA 域也清了（模板同构不可分，显式取舍）。
3. **LongBench-Pro（对抗构造）**：qa **P 0% / R 0%**（T3 全是 MC 模板形态，同 v2 原因）；summarize **P 91.2% / R 85.8%**。

> 鲁棒性混入集（LB-Pro + v2）上 qa 的低 recall/precision **不代表 qa 判定质量**——这两个数据集的 QA 子集恰好全部落在"MC 模板同构"这一显式放弃的区域。qa 判定质量看 LongBench。

| **合计**                      | 203 | **0 (0%)** | 194 (95.6%) |

### qa 指标

| 指标                            |                    值 | 说明                                    |
| ------------------------------- | --------------------: | --------------------------------------- |
| recall                          | 2/300 =**0.7%** | Single-Doc QA 1/175、Multi-Doc QA 1/125 |
| precision                       |   2/2 =**100%** | 非 QA 域 0 违规 → 无假阳性             |
| 对照（裸 question，无选项渲染） |     R 277/300 = 92.3% | 证明损失全部来自选项模板，不是规则变弱  |

**为什么是 2/300**：官方 0shot 模板把所有 300 条 QA 渲染成 `What is the correct answer…\nChoices:\n(A)…(B)…` 的统一形态，`neg_mc_enum`（MC 双连行负规则）命中即清零。全 v2 只有 2 条因 choices 内容跨行断开等原因逃过双连行匹配（如选项内含换行、长句折行），这 2 条以 wh 问句信号判回 qa。**同一条规则同时实现了"非 QA 四域 194→0"和"QA 291→2"——这是精度优先口径下的一枚硬币两面**：v2 官方模板下 MC 形态在 QA/ICL/Code/Dialog/Struct 五域同构，规则层面不可分。真实线上流量若不用此模板，qa 判定不受影响（裸 question 对照 R 92.3%）。

### qa 指标（真值 = T3，120 条）

| 指标      |                  值 | 说明                                                     |
| --------- | ------------------: | -------------------------------------------------------- |
| recall    | 0/120 =**0%** | 120 条全部判 other                                       |
| precision | 0/112 =**0%** | 112 个 qa 预测全部来自边界任务（见上表），T3 自身 0 判对 |
| 基线对照  |    R 82/120 = 68.3% | 基线 P = 82/285 = 28.8%                                  |

**原因与 v2 完全相同**：T3 是 MC 选择题（题面自带 `A、B、C、D` 选项或"答案选项字母"），与 T5 引用对齐、T7 合规检查的 MC 形态同构。基线时 T3 判对 82 条的代价是非 QA 任务 373 条违规；清零违规的同时 T3 归零。**取舍方向由口径决定**：混入集的目的是防误判（非 QA 任务被压成 QA/摘要prompt会选错压缩策略），T3 掉 other 在线上走 system 模板兜底路径。

### summarize 指标（真值 = T4，120 条）

| 指标      |                       值 | 说明                                                   |
| --------- | -----------------------: | ------------------------------------------------------ |
| recall    | 103/120 =**85.8%** | 基线仅 18/120，**本次 +85**                      |
| precision | 103/113 =**91.2%** | 10 个 FP 全部是 T10 规则归纳（"总结相关规律，判断…"） |

**T4 是纯增益项**：修复前只有 18 条被 `en_summary_suffix` 等模板形态覆盖；补 `zh_imperative_abstract`（整理/归纳/提炼成…摘要、给出摘要、字的摘要）和 `en_generate_summary`（generate a summary）后覆盖 103 条。

**漏判的 17 条形态**（判 other，未误判成 qa，精度无损）：

- "Produce a query-focused summary (≤150 words)…" / "Generate a focused summary (350 words maximum)…"——**限定主题的生成式摘要**（query-focused / focused on X），措辞重心在限定词不在"摘要"动词上
- "Provide an abstract of no more than 150 words…"——用 **abstract** 而非 summary/摘要（学术摘要措辞）
- "在不超过400字内生成对上述文本全篇的高覆盖摘要"——"生成对…的高覆盖摘要"的插入语把动词和宾语隔开
- "According to the summary of … above, a summary…"——指代型开头触发负规则

这些是可继续收敛的方向（abstract 同义扩展、query-focused 变体），但每条都要过三重探针（LongBench 误伤=0 / T3-T4 误伤=0）才值得加——T10 的 10 个 FP 说明 summarize 正规则越宽，边界任务的渗入越多，收敛边际收益递减。

## 五、三个数据集横向对比

| 数据集        | qa P / R                                            | summarize P / R                                   |             other 误判 | 定位                           |
| ------------- | --------------------------------------------------- | ------------------------------------------------- | ---------------------: | ------------------------------ |
| LongBench     | **95.1% / 99.9%**（剔 qmsum 后 100% / 99.9%） | **100% / 85.2%**（剔 qmsum 后 100% / 100%） |                 0/1000 | 真实流量，质量基准             |
| LongBench-v2  | 100% /**0.7%**                                | —（无 summarize 真值）                           |                  0/203 | 对抗混入：MC 模板同构区        |
| LongBench-Pro | 0% /**0%**（T3 全是 MC 形态）                 | **91.2% / 85.8%**                           | 122/1260（全边界任务） | 对抗混入：MC 同构 + 边界裸问句 |

**读法**：

- 精度优先原则在**真实流量上完胜**：qa/summarize precision 100%（qmsum 豁免外），other 零误判。
- 两个对抗集上的低 recall **都集中在 MC 模板同构区**（v2 QA 域 + LB-Pro T3），这是为换取"非 QA 任务零误判"（v2 194→0、LB-Pro 机械类 108→0）付出的对价，不是规则能力缺陷——裸 question 对照（v2 QA R 92.3%）证明拿掉模板后 qa 判定能力完好。
- summarize 在三个数据集上 precision 都 ≥91%，LB-Pro 上还净赚 85 条 recall，说明"摘要"类信号比"问句"类信号更鲁棒（祈使动词形态比疑问句形态更难被非摘要任务借用）。

## 六、附录：指标口径说明

- **触发**：`long_text` > 2000 字符才进分类器（真实系统短文本不压缩不分类）。LongBench 未触发共 10 条（multifieldqa_zh 3、multi_news 4、vcsum 3），v2/LB-Pro 全触发；BFCL 另有 185 条未触发（单轮环境 JSON 短）。
- **未触发样本的计数**：不计入 recall 分母（它们没进分类器），也不计入 precision 分母。
- **qmsum 豁免**：141 条问句形态的摘要请求判 qa 属"线上方向正确"的既定设计代价（文档问答就该路由 qa），单列不设门槛；本报告两处口径（含/剔 qmsum）都给出。
- **工具名**：`classify_pipeline(user, long_text, system_prompt)`；LongBench system=官方子集模板，v2/LB-Pro system=""（对齐各自官方评测管线）。
